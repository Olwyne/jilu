# i18n Design — EN/FR Support

**Date:** 2026-07-21  
**Stack:** React 19 + Vite + Firebase + react-i18next

---

## Summary

Add full EN/FR translation support to Jilu. Browser language auto-detected on first load. User can override in Account settings. Preference persisted in both localStorage (device) and Firestore `settings.language` (cross-device).

---

## Architecture

### New files

```
src/
  i18n/
    index.js      # i18next init with browser language detector
    en.json       # all English strings, single namespace
    fr.json       # all French strings, single namespace
```

### Modified files

| File | Change |
|------|--------|
| `src/main.jsx` | Import `./i18n/index.js` (side-effect init before render) |
| `src/hooks/useAppData.js` | Add `language: null` to `EMPTY_DATA.settings` |
| `src/App.jsx` | Sync Firestore `settings.language` → i18next on login; pass `onChangeLanguage` handler to AccountView; convert `ROUTE_COPY` to `getRouteCopy(t)` function |
| `src/components/account/AccountView.jsx` | Language switcher UI; `PREF_ROWS`/`PLAYBACK_ROWS`/`PRIVACY_ROWS` computed inside component with `t()`; all strings via `t()` |
| All other components (~14 files) | Replace hardcoded strings with `t('key')` |
| `src/setupTests.js` | Init i18next with `lng: 'en'` for tests |
| Affected test files | Update string assertions to English equivalents |

## Language Detection & Persistence

### Detection order (on init)
1. `localStorage['i18nextLng']` (set by i18next automatically on change)
2. Browser `navigator.language`
3. Fallback: `'en'`

### On user login
```js
// In App.jsx, after data loads:
useEffect(() => {
  if (data.settings.language) {
    i18n.changeLanguage(data.settings.language)
  }
}, [data.settings.language])
```

### On language change (in AccountView)
```js
function handleChangeLanguage(lang) {
  i18n.changeLanguage(lang)                          // updates localStorage
  onChangeLanguage(lang)                             // mutates Firestore settings.language
}
```

## i18next Init (`src/i18n/index.js`)

```js
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'
import LanguageDetector from 'i18next-browser-languagedetector'
import en from './en.json'
import fr from './fr.json'

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: { en: { translation: en }, fr: { translation: fr } },
    fallbackLng: 'en',
    supportedLngs: ['en', 'fr'],
    interpolation: { escapeValue: false },
    detection: {
      order: ['localStorage', 'navigator'],
      cacheUserLanguage: true,
    },
  })

export default i18n
```

## Component Usage Pattern

```jsx
import { useTranslation } from 'react-i18next'

export default function MyComponent() {
  const { t } = useTranslation()
  return <button>{t('common.save')}</button>
}
```

## Testing

`src/setupTests.js` initializes i18next with `lng: 'en'` so all tests run against English strings. Test assertions updated from French to English equivalents.

```js
// setupTests.js
import './i18n/index.js'
import i18n from './i18n/index.js'
i18n.changeLanguage('en')
```

## Out of Scope

- More than 2 languages (architecture supports adding more later — just add a JSON file)
- ICU plurals (no plural strings identified in current codebase)
- RTL layout support
- Date/number locale formatting (can be added per-component with `Intl` if needed)
